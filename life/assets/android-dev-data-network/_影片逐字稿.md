> 對應文章：android-dev-data-network

---

## 00:00 開場

[螢幕] 片頭或口播。

[旁白]
嗨，我是智慧喵。到目前為止，我們的 Android App 能顯示畫面、能互動了，但它一樣有兩個問題：一關掉資料就不見，而且不會連網。這一集就來補這兩塊。如果你走過 iOS 的資料與網路篇，觀念完全共通，只是換工具。分兩部分：本機記資料、網路抓資料。

---

## 00:20 DataStore

[螢幕] 打出 DataStore 存值。

[旁白]
存少量、簡單的設定，像暱稱、開關，用 DataStore，這是 Google 現在推薦的做法，取代舊的 SharedPreferences。概念就是用一把鑰匙存一個值，會自動保存，App 關掉再開資料還在。對應 iOS 的話，它就相當於 UserDefaults，只適合小資料，不是資料庫。

---

## 01:50 Room

[螢幕] 打出 Entity data class。

[旁白]
當你要存的是大量、有結構的資料，比如一份待辦清單、一堆筆記，就用 Room。它是 Android 官方的資料庫方案，底層是 SQLite，但幫你包成好用的介面。
Room 核心三塊：Entity 定義一筆資料長怎樣、DAO 是存取的方法、Database 是資料庫本體。這集先讓你知道這個分工：小設定用 DataStore，清單記錄用 Room。實作細節等你真的要做再深入。

---

## 03:20 名詞

[螢幕] API / JSON / Retrofit / 協程 流程圖。

[旁白]
連網的部分。先懂幾個名詞。API 是網路上的資料窗口。JSON 是回傳資料的格式。Retrofit 是 Android 社群最常用的網路請求函式庫，把呼叫 API 寫得很簡潔。協程，是 Kotlin 處理非同步的機制，用 suspend 標記，對應 iOS 的 async await。流程一樣是發出請求、收到 JSON、轉成 Kotlin 資料、顯示在畫面。

---

## 04:50 定義資料與 API 介面

[螢幕] 打出 data class 與 interface + @GET。

[旁白]
先照 JSON 定義一個 data class，它很像 iOS 的 Codable。再用 Retrofit 定義這個 API 怎麼呼叫，@GET 告訴它去打哪個路徑，suspend 表示這是協程的非同步函式。Retrofit 會自動幫你發請求、把 JSON 轉成資料，不用手動解析。

---

## 06:20 Retrofit 實際抓（重點）

[螢幕] 打出 loadWeather、try/catch，跑公開 API。

[旁白]
在協程裡呼叫。這個呼叫會等它回來，但不卡住畫面。重點跟 iOS 一樣：網路一定有出錯的時候，斷線、逾時、格式不符，所以務必用 try catch 處理，別假設它一定成功。
我實際抓一個公開 API 給你看，成功印出資料了。

---

## 08:50 在 Compose 顯示

[螢幕] 打出 LaunchedEffect 與 state。

[旁白]
最後把抓到的資料放進 state，畫面就自動更新，這就是上集的狀態驅動。這個 LaunchedEffect 是 Compose 的機制，畫面一出現就執行裡面的協程工作，很適合載入資料，對應 SwiftUI 的 point task。
