## 00:00 開場

[螢幕] 片頭或口播。

[旁白]
嗨，我是智慧喵。到目前為止，我們的 App 能顯示畫面、也能互動了，但它有兩個大問題：一關掉，資料就不見了；而且它不會跟外界溝通。這一集，我們就來補這兩塊，讓 App 從玩具變成真正實用的工具。
分兩部分：先學怎麼在本機記住資料，再學怎麼從網路抓資料。

---

## 00:20 UserDefaults

[螢幕] 打出 UserDefaults 存值、讀值。

[旁白]
App 常常要記住一些小設定，像是使用者的暱稱、深色模式開了沒。這種小資料，用 UserDefaults 最簡單。
它的概念就像用一把鑰匙存一個值，下次用同一把鑰匙就能拿回來，而且會自動保存，App 關掉再開，資料還在。
不過要注意，UserDefaults 只適合存少量、簡單的資料，它不是資料庫，別拿來存大量清單。還有兩點很重要：一，資料存在使用者的裝置本機，不是雲端，換手機不會自動帶過去；二，它沒有加密，所以絕對不要拿它存密碼、金鑰這種機密資料，那要用 Keychain 鑰匙圈。UserDefaults 存暱稱、開關這種不敏感的設定就好。@AppStorage 底層就是 UserDefaults，特性完全一樣。

## 01:50 @AppStorage

[螢幕] 打出 @AppStorage 綁 TextField。

[旁白]
在 SwiftUI 裡有個更順手的寫法，叫 @AppStorage，它直接把 UserDefaults 綁到畫面上。
你看，我做一個記住暱稱的輸入框。使用者在這裡改了名字，它會自動存進 UserDefaults、畫面也自動更新，App 重開名字還在。一行就搞定存取，非常好用。

## 03:20 三個名詞

[螢幕] API / JSON / URLSession 流程圖。

[旁白]
接下來是重頭戲，連網。先懂三個名詞。
API，你可以想成網路上的一個資料窗口，你按它的規則發請求，它回你資料。JSON，是回傳資料最常用的格式，長得像一堆鍵配值。URLSession，是 Swift 內建用來發網路請求的工具。
整個流程是這樣：App 發出請求，伺服器回傳 JSON，我們把 JSON 轉成 Swift 資料，再顯示在畫面上。

---

## 04:50 Codable

[螢幕] 打出 struct Weather: Codable。

[旁白]
Swift 有個很優雅的機制叫 Codable，能自動把 JSON 對應到你定義的資料結構。你只要照 JSON 的欄位，定義一個對應的 struct，欄位名稱對得上，Swift 就自動幫你轉換，不用一個一個手動解析。

---

## 06:20 URLSession 實際抓（重點）

[螢幕] 逐行打出 fetchWeather，用 async/await、do/catch、guard let。

[旁白]
把它們組起來。我用現代 Swift 的 async await 寫法，比舊的寫法好讀很多。
第一步準備網址，用 guard let 先確認網址有效。第二步發出請求，這個 await 表示在這裡等它回來，但不會卡住整個 App。第三步把回傳的 JSON 解析成我們的 Weather。最後拿到資料。
這裡有個重點：網路很容易出錯，斷線、逾時、格式不符都可能發生，所以一定要用 do catch 處理錯誤，不能假設它一定成功。

[螢幕] 瀏覽器打開 JSONPlaceholder 網址，展示回傳的 JSON。

[旁白]
這裡回答一個很多人的疑問：我怎麼知道 API 有哪些欄位可以抓？最簡單的方法，把 API 網址直接貼到瀏覽器打開就看得到。我用大家最常練手的 JSONPlaceholder，打開這個 todos 的網址，你看，它回傳 userId、id、title、completed 四個欄位，型別一目了然。你的 struct 就照這個抄，欄位名稱跟型別對上，Codable 就自動幫你轉。

[螢幕] 照 JSON 寫 Todo struct，換上真網址，模擬器跑出真資料。

[旁白]
我照剛剛看到的欄位定義一個 Todo struct，把網址換成這個真的 JSONPlaceholder 網址，執行。你看，真的抓到資料了，畫面顯示第一筆的標題。把網址結尾的數字改一改，內容就跟著換，你已經在真的串 API 了。永遠記得這個流程：先打開網址看結構、再照著寫 struct。
補一個常見狀況：如果你顯示抓取失敗、錯誤裡有 Code 減 1003 找不到伺服器，通常是連不到網路。最常見是你跑在 My Mac 上被沙盒擋住，要去 Signing & Capabilities 的 App Sandbox 勾選 Outgoing Connections。最省事的做法是改用 iPhone 模擬器跑，模擬器沒這個限制，學習階段建議都用模擬器。

## 08:50 在 SwiftUI 畫面呼叫

[螢幕] 打出 .task 與 @State。

[旁白]
這裡要講清楚一個新手常卡的點：剛剛那個抓資料的函式，要放進 View 的 struct 裡面當一個方法，不是丟在外面。我把它放進來、跟 body 平行，然後在點 task 裡呼叫它，抓到的資料存進 @State，畫面就自動更新，這就是上一集學的狀態驅動。所以剛剛獨立的 fetchWeather，其實就是這裡放進 View 的 loadWeather，同一段邏輯、只是裝到對的位置。這個點 task 是 SwiftUI 的好用修飾符，畫面一出現就自動執行裡面的載入工作，很適合拿來抓資料。
