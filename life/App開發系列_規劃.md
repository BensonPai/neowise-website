## 系列定位

- **對象**：完全沒寫過 App、或只會一點程式，想從零學到能上架、能賺錢的人。
- **主軸**：iPhone（iOS）開發完整指南 → Android 開發完整指南。
- **每篇必涵蓋的五個面向**（來自需求）：開發工具 → 開發流程 → 上架商店 → 費用 → 賺錢方式。
- **智慧喵自己的角色**：本身開發過 iPhone 相片備份 App，可自然帶入實戰經驗與工具頁導流。
- **分類**：一律 `category: "科技"`；標題掛前綴【App 開發指南】方便讀者辨識同系列。
- **每篇底部**：放系列導覽連結（總覽篇 + iOS 路徑 + Android 路徑）。

## 三層結構總覽

### 第一層：總覽篇（1 篇）— 系列入口

**slug: `app-dev-complete-guide-overview`**
標題方向：《iPhone 與 Android App 開發完整指南：工具、流程、上架、費用、賺錢一次看懂》

內容綱要（五面向各給全貌，iOS/Android 並列比較）：
1. 開場：想做 App 的人最常卡在哪（不知道從何學起、怕花錢、怕學了不能變現）。
2. 開發工具：iOS（Mac + Xcode + Swift/SwiftUI）vs Android（任何電腦 + Android Studio + Kotlin）。
3. 開發流程：需求 → 設計 → 開發 → 測試 → 上架的共通骨架。
4. 上架商店：App Store vs Google Play 的審核、時間、難度差異。
5. 費用：開發者帳號費、電腦/裝置成本、其他隱藏成本。
   > **費用數字規則**：寫文時務必上網查一次最新官方價（Apple Developer Program、Google Play Console），文中標明「查證時間：YYYY-MM-DD」，避免價格過期誤導讀者。
6. 賺錢方式：付費下載、App 內購買、訂閱、廣告、接案、企業內部工具。
7. 收尾：給一張「該先學 iOS 還是 Android」的決策建議，帶出後續兩條學習路徑。

> 這篇要放整個系列的「地圖」，讓讀者知道接下來會有 iOS 路徑與 Android 路徑。

> **路線決定（2026-09-27）**：走「扎實系統學習路徑」，不做 30 天速成挑戰篇。系列維持三層：總覽篇 → iOS 系統路徑 → Android 系統路徑。

### 第四層：跨平台開發總覽（1 篇，補充篇）

**slug: `cross-platform-app-dev-overview`**
標題方向：《【App 開發指南】一套程式碼兩邊跑？Flutter、React Native、KMP 跨平台方案怎麼選》

**定位（方案 1）**：只「介紹＋選型」，**不教實作**。讓讀者知道除了原生，還有「一次寫、兩邊共用」這條路，並能判斷自己適不適合。若日後讀者反應熱烈，可把這篇當入口，往下擴充成完整的 Flutter 實作系列（升級成方案 3）。

內容綱要：
1. 開場：學原生要學兩套，有沒有「寫一次、iOS/Android 都能跑」的方法？
2. 原生 vs 跨平台：各自優缺點（效能/體驗 vs 省時/省維護）。
3. 三大方案（寫文時上網查最新市佔與版本，標查證時間）：
   - **Flutter**（Google，Dart）：市佔最高、畫面一致性最好、適合快速做 MVP。
   - **React Native**（Meta，JS/TS）：人才庫最大、會前端上手最快、生態豐富。
   - **Kotlin Multiplatform（KMP）**：共用商業邏輯、UI 走原生，成長最快。
4. 給初學者的選擇建議：想一個人做雙平台省力 → Flutter；已會前端 → RN；想保留原生體驗 → KMP。
5. 誠實提醒：跨平台仍需懂各平台基礎（上架、權限、憑證框架幫不了）；深度功能仍要碰原生。所以「完全不學原生、只學跨平台」不實際 → 呼應本系列「先原生打底」的主張。
6. 收尾：帶回原生學習路徑；預告若有需求會出 Flutter 實作系列。

> **放在哪讀**：這是補充篇，建議讀者在讀完總覽篇後、或走原生路徑遇到「要不要兩邊都做」時來看。

## 完整學會兩個平台的總時間

| 情境 | iOS | Android（已會 iOS 後） | 合計 |
|------|-----|----------------------|------|
| 每天 1~2 小時（上班族） | 3~4 個月 | 1.5~2 個月 | 約 **5~6 個月** |
| 每天 3~4 小時 | 6~8 週 | 4~5 週 | 約 **3 個月** |
| 全職投入 | 3~4 週 | 2~3 週 | 約 **6~7 週** |

> 這是「能獨立做出並上架一個中小型 App」的程度，不是精通。精通（複雜架構、效能優化、上架熱門 App）需要持續累積實戰專案，通常以年計。

## YouTube 影片配合（沿用既有整合機制）

本系列落在智慧喵三條內容線的「**科技與工具**」線，是「工程師/開發者視角」的獨特內容，AI 說書頻道複製不了，很適合雙平台經營。做法沿用 `YouTube與部落格整合計畫.md` 的「一個主題、兩種產出」模型：

| | 部落格文章 | YouTube 影片 |
|---|-----------|-------------|
| 角色 | 文字深入版，抓 SEO（步驟、程式碼、截圖可複製） | 口說＋螢幕錄影版，抓影音流量 |
| App 系列優勢 | 貼程式碼、放流程圖 | **螢幕錄影示範 Xcode 操作、App 實際跑起來**（文字難講清楚的部分靠影片） |
| 互導 | 文末自動嵌入影片、開頭自動加提示條 | 說明欄放對應文章連結 |

**技術面（已現成，零開發）**：產生器已支援 front-matter 欄位——
- `youtube`：填影片 ID 或任何 YouTube 網址（youtu.be / watch?v= / shorts 都行）。有值就自動在文末嵌入播放器、開頭加「🎬 影片版」提示條、首頁卡片加 🎬 標記；留空則不顯示。
- `youtube_title`（選填）：自訂影片區塊標題，不填預設「🎬 影片版」。

**執行流程**：
1. 文章先寫、先發（front-matter 先留空的 `youtube: ""` 佔位）。
2. 依文章內容錄對應影片（以螢幕錄影示範操作為主）。
3. 上傳 YouTube → 把影片 ID 填進該篇 `youtube:` → 重跑 `build-life.bat` → 影片自動嵌入。
4. Kiro 可在寫每篇文章時，順手產一份「影片口說腳本大綱」供錄影用（呼應整合計畫第五點）。
